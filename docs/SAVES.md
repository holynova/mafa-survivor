# 存档备份与恢复（alpha.14）

入口：主菜单 → 征战记录 → 存档备份。保存范围是全部战绩、当前玛法结晶余额、已解锁章节与玛法天赋，不包含正在进行的战斗检查点。战斗刷新会回到本波起点，可从主菜单继续。

- 导出完整备份：下载版本1的JSON，包含所有记录，不受界面最近10条限制；若下载受限，可展开JSON复制保存。
- 选择备份文件或粘贴JSON后预览，显示结晶、记录条数、章节的前后对照。此时不写入；勾选“我确认替换本机存档”后才能确认。
- 完整替换，不合并或叠加结晶。导入保留原runId，重复提交已经存在的结算不会再发奖励。
- 写入前，把本机原数据保存在同一个IndexedDB事务中的恢复点；清空旧记录、写入新记录、更新进度与恢复点一起提交或一起回滚。容量不足、插入失败等不会留下半份存档。
- 恢复后可“预览恢复前备份”，再次确认恢复。只保留最近一次恢复前的数据，再次恢复会更新这一份；需长期保留请另行导出。
- 预览与确认间若其他标签页产生结算或解锁，拒绝过期预览，要求重新选择并预览。
- 无法导出正常备份时可下载本机原始数据；覆盖异常进度后，其原样数据也保留在恢复点，可下载排查。异常原始文件不冒充可导入的正常备份。
- 波次边界续玩是独立的IndexedDB检查点，不属于导出备份：主菜单可继续或放弃；战场中途刷新回到本波起点，怪物、掉落与弹体不保存；结算或恢复备份会清除检查点。

格式为`mafa-survivor-save`、`version=1`，内含`progress`（schemaVersion=1）与`runs`。alpha.15起`progress`可含`talents`（8个已知天赋ID，整数0–5），缺失时按空天赋迁移；未知ID、越界等级或非整数拒绝导入。限制5MB／10,000条；拒绝未知版本、未知字段／职业／地图、重复runId、非法数字、测试局记录等。旧记录允许缺少职业、地图、回复与承伤统计；IndexedDB v1的旧战绩迁移仍只结算一次。数据库继续使用v2，新恢复点存放在已有meta表，不删库升级。

这是离线单机的备份格式，JSON可由本机用户编辑，不提供联网防作弊验证。网页来源决定浏览器存储空间；本地开发版与GitHub Pages的进度彼此独立，可用导出的文件转移。没有云端自动同步、任意损坏自动修复、战场逐帧续玩或设置备份；玛法天赋自alpha.15起包含在进度与备份中。

验证：`tests/save-backup.test.ts`覆盖完整导出、替换／撤回、异常保留、过期预览、事务中断、并发恢复、旧记录与格式边界。真实浏览器文件选择、下载、预览、取消、确认、重载及撤回证据见QA.md。
