# 幸存者类游戏最佳实践：一手资料备忘

检索日期：2026-11-17。用途：为 alpha.40 审查提供外部依据。此文件不声称完成了游戏实机测试；项目具体问题、代码位置与优先级另见主审查报告。

“最佳实践”不是统一数值配方。以下区分 **来源实际支持的结论** 与 **对本项目的推导建议**。没有资料能证明所有此类游戏都应采用同一局长、八级技能、固定胜率或固定升级秒数。

| S1 [Vampire Survivors 官方商店](https://store.steampowered.com/app/1794680/Vampire_Survivors/) | poncle 将其描述为极简操作的时间生存游戏；官方入门建议先拿两三个进攻武器，集中逐个升级，局外强化可免费退款尝试。 | 主目标应是形成少数互补核心技能的构筑，而非平均升级所有技能。升级卡应显示下一等级的实际变化；提供尝试构筑的空间，同时明确局内换技的成长损失。 |

| S7 [Microsoft XAG 103：多通道提示](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103) | 关键视觉/音频信息应通过多种感官渠道表达，颜色不应成为唯一识别依据。 | Boss到场、低血量、受伤与危险攻击同时有可见提示和声音；精英不只靠变红，还应有尺寸、轮廓/标识与血条。手机静音时仍能理解事件。 |
| S8 [Microsoft XAG 105：音频可访问性](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/105) | 音乐、效果和其他关键声音应能独立调节，避免重要信息被其他声音淹没。 | 采用音乐、环境、战斗效果、UI/奖励等分组；关键预警和玩家受击保留优先级，限制高频金币与群怪叠音。分类优先级是项目设计建议，不是该指南规定的固定总线表。 |
| S9 [Microsoft XAG 117：运动与视觉干扰](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/117) | 自动运动/闪烁可造成障碍，应提供控制；不可避免的动态背景上可提供不透明文字底板。 | 提供屏震、闪白、伤害数字、装饰粒子强度选项；保留默认半透明传奇风弹框，同时允许高对比底色。不要把“更透明”当作所有设备上的可读性提升。 |
| S10 [MDN：Audio for Web games](https://developer.mozilla.org/en-US/docs/Games/Techniques/Audio_for_Web_Games) | Web Audio 可精确同步音频，并通过循环层或轨道变化响应游戏环境，音乐可参与悬念与鼓励的表达。 | 给地图平静/压力/首领/结算设计音乐状态与淡入淡出；优先核查已授权原版音乐来源。若没有原版分轨，不强求分层混音，可用完整曲目与过渡；不以合成音替代用户指定原版素材。 |
| S11 [MDN：Web Audio API best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices) | 长曲通常适合媒体流，短效果适合缓冲；浏览器音频上下文应从用户手势创建/恢复；用户应能调节和静音。 | 检查首次开始、恢复存档、切后台再回来、静音切换等路径；音乐不要全部预解码常驻。仅单测触发事件不能证明手机实际发声正确。 |

## 最近的同类平衡实践补充

[Brotato 官方公告](https://steamcommunity.com/app/1942280/announcements/)中2026-11-06的“Balancing in Open Beta”明确先在公开测试中实验，再更新默认版本；11月12日“Balancing Patch”继续要求玩家反馈。具体条目包括首次攻击前等待、减少某波弹幕、修正脚部碰撞时机。这支持将行为可读性、经济、操作体验与强弱一起调，而不是仅追求胜率数字。

对本项目的推导：保留冻结版本与固定种子对照，同时补真人反馈；分别看死亡来源、受伤时间分布、首次成型/进化时间、构筑选择率与放弃原因。机器人通关率不是玩家留存或难度感受。这里没有声称该团队公开了自己的遥测系统。

## 建议采用的审查验收问题

以下是研究者为本项目拟定的检查清单，不是上述来源给出的统一行业阈值：

1. 玩家不打开攻略，能否理解这局要培养哪两三个核心技能？升级是否产生可感知的行为变化？
2. 成型后是否有一段能体验力量的窗口，而非敌人即时按输出膨胀？压力是否有峰谷？
3. 死亡后能否说明是哪个敌人、哪种攻击、什么位置造成？预警与真实伤害几何是否一致？
4. 静音、色觉差异、强光、小屏、低画质下，危险是否仍能被辨认？
5. 原版人物、装备和地图是否形成清晰前后景？是否有“资源真实但组合方式不可读”的问题？
6. 音乐是否随局势变化，关键声音是否能穿过怪群叠音？首次启动和后台恢复是否实际可听？
7. 战场、三选一和暂停菜单是否都可单手触达？屏幕边缘/系统手势/滚动是否会误移动角色？
8. 低端真机在后期怪群和多技能叠加下，帧时间、加载、内存和温度是否可接受？测试必须注明设备、浏览器和场景。
9. 保存/恢复是否保留本局挑战状态和奖励约束？换技与重试是否产生可反复利用的空隙？
10. 是否从玩家反馈到复现样本到回归测试形成闭环，而非把测试数量当成“好玩”的证明？

## 证据边界

- 已打开并核实以上文本来源。Noclip《The Making of Vampire Survivors》虽找到开发者访谈视频，但本轮未完整取得/核实逐字稿，因此没有从视频目录推导具体设计论断。
- 没有找到足以支持“Brotato官方固定理想胜率/升级频率”的一手证据，不采用第三方分析站的推测数字。
- 跨类型资料只能支持原则；《求生之路》和《VALORANT》的具体调度时长、敌人规则、渲染技术不应原样移植。
- 美术来源、版权授权、实际资源映射与工程性能须由项目检查另行确认；研究资料不替代这些验收。
